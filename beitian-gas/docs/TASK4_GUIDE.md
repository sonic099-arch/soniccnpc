# 任务4：生产筛查页面使用说明

本阶段实现首页统计、气井列表、异常井列表、单井7参数曲线；继续使用任务3的分析引擎和数据库结构。默认1000口演示井；额外的手工测试井正常保留。所有演示参数和曲线不构成现场工艺判定标准。

## 更新并启动

Win11用户在WSL2 Ubuntu24.04终端操作。停止旧服务（Ctrl+C），进入实际的 `soniccnpc/beitian-gas` 项目目录：

```bash
git pull --ff-only
source .venv/bin/activate
python -m pip install --no-deps -e ./backend
npm --prefix frontend ci
python scripts/dev.py
```

继续使用Python3.12；任务4无新增数据库迁移，仍为0002_analysis_results，已有work/dev-postgres数据保留。使用自管PostgreSQL时按README分别启动服务和前端。普通打开网页不需要安装Playwright浏览器。

如果此前通过Download ZIP覆盖过源码，git pull可能提示本地修改；先保存本地修改，再合并更新，禁止强制清库或覆盖凭据。GitHub网络不可用时，可用Windows浏览器下载仓库ZIP，把内部beitian-gas文件复制到原项目；保留 `.env`、`.venv`、`.git`、`work`，再执行安装与启动命令。此方式不更新本地Git提交记录。

打开 `http://localhost:5173/`，Ctrl+Shift+R刷新。顶部显示“任务4 · 生产可视化”。侧边“智能分析系统 · 第一阶段”是整个项目阶段名称，不代表旧代码。

## 首页统计

首页按数据库聚合登记井数、分析井数、可信正常、疑似异常、措施影响、数据待核实、工况待核实和未分析。状态分布饼图和工区堆叠图均由真实查询结果生成，不写死演示计数；点击状态卡进入对应井列表。使用搜索、工区、状态筛选后，卡片数字表示筛选范围。

“分析任务”默认选择最近完成的一次引擎任务，可以切换最近100次任务（更早任务可按run_id链接访问）。数据窗口始终显示北京时间，结束不含。各页跳转携带任务ID，不会把不同分析窗口的状态混在一起。筛选参数和页码保存在URL中，刷新或复制链接可以恢复。

如果之前先以10月22日为终点分析全部待核实，再明确回到10月15日重新分析，首页会显示最后完成的正确任务。原最新状态快照仍按数据窗口保护，任务3原接口兼容保留。历史结果不表示当前实时井况；需要新判断时到“运行分析”明确时间窗口后执行。

## 气井列表

进入 `/wells`：

1. 按井号搜索、选择工区、筛查状态或异常类型，点击“查询”。点击“清空筛选”保留当前任务并清除其他条件。
2. 需要按事件发生时间查井时设置“事件时间”，输入按浏览器本地时区解析；建议Windows时区设为北京时间。此筛选要求井有与区间重叠的分析事件，正常井或无事件井不会匹配。
3. 列表按井号稳定排序，每页50条；未参与本次任务的登记井显示“未分析”，不引用旧任务或当作正常。
4. 点击井号或“查看曲线”，进入单井页面，保持当前分析任务。

“分析窗口终点”是该任务的判断时点，不是数据库最后更新时间。演示井有“演示”标记；井号可变，页面内部始终使用稳定Well UUID关联。

## 异常井列表

进入 `/anomalies`，默认按井汇总、一口井只出现一次，并排除可信正常井。措施影响、数据/工况待核实和未分析井也保留，便于人工处理。页头显示单位“口井”。

点击“切换为逐事件列表”，显示事件、规则编号及版本、开始时间；一口井可能有多个事件，单位变为“条事件”。点击“证据”查看规则快照、原始代表采样、生产上下文和人工复核记录。疑似积液/冻堵只为辅助提示，不自动确诊。未分析井没有引擎事件，应先到运行分析页面执行。

搜索、工区、状态、异常类型和事件时间可组合。事件时间采用半开区间重叠：event.started_at小于查询结束，event.ended_at为空或大于查询开始。它不是“仅看开始在区间内”的条件，因此持续事件跨越开始边界时仍保留；筛选不会重算规则。

## 单井七参数曲线

单井路径 `/wells/气井UUID`，上部显示井号、工区、筛查/生产状态、最新原始采样和所选分析任务。默认曲线使用该任务分析窗口，即使任务未覆盖本井也会明确显示“未分析”。没有任何分析任务时，曲线以该井最新采样为终点回看14天。

七个参数分别为油压、套压、井口回压（MPa）、瞬时流量（m³/h）、累计流量（m³）、气流温度（℃）、产液量（m³/d，第七参数暂定）。各自纵轴有单位；瞬时流量采用较宽曲线区，其他六项并列显示。横轴、悬浮时间和事件表统一显示北京时间。

- “分析窗口”恢复该任务时间；“末7/14/30天”以该任务窗口终点回看，不以今天回看历史演示数据。
- 自定义起止使用本地时区，点击“更新曲线”；最长90天且最多20000个原始采样，超限明确提示缩短范围，不静默截断。
- 鼠标悬浮显示原始数值，七图共享时间轴交互；滚轮或拖动底部滑条缩放。
- 蓝色虚线标措施实际开始，浅蓝区域表示其有效区间；措施开始早于窗口时只显示裁剪后的有效区域，不伪造窗口内开始点。
- 橙色虚线标所选任务异常实际开始；事件表可打开对应证据。窗口外起点不强行移到边界。
- 曲线不平滑、不插值，空值及已识别采样缺口断线，累计量复位原样显示。窗口无采样时明确显示空数据。

下方有措施表、开关井操作、异常/影响事件和全部规则执行结果。切换曲线范围不会修改这些规则判断；新规则版本需重新执行分析。当前源表修改后曲线可能变化，历史证据仍保留分析时代表采样、上下文和输入摘要，不是完整源数据库归档。

推荐从列表搜索：演示-BT-0001（正常）、0003（减产）、0006（正常泡排）、0007（泡排效果不佳）、0012（缺失）、0013（累计复位）。这些井号对应默认种子批次，仅为演示定位。

## 对照结果

默认1000演示井、14天、规则1.0.0，分析窗口北京时间2026-10-01 08:00至2026-10-15 08:00：可信正常308、疑似异常385、措施影响77、数据待核实230、工况待核实0。保留原手工测试井时通常登记1001、数据待核实231，需复核井693。修改规则、数据或分析范围会改变结果，页面不会强制匹配这些数字。

## 自动测试

```bash
python -m pytest backend/tests --junitxml=work/task4-backend.xml
npm --prefix frontend test -- --reporter=junit --outputFile=../work/task4-frontend.xml
npm --prefix frontend run build
cd frontend
npx playwright install chromium
cd ..
python scripts/verify_web.py --report work/task4-full-check.json
python scripts/export_openapi.py
```

verify_web建立独立临时PostgreSQL，装载1000演示井及一口日期较新的手工井，先后分析两个窗口，逐井检查展示状态，再用真实Chromium验证首页、列表、证据、七参数SVG、移动页面及筛选。随机本地端口避开原有服务，结束停止进程并清理测试库，不接触现有开发库或 `.env` 数据库。

已有系统Chromium时可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`，未安装浏览器可加 `--skip-browser`只做API核验，不能当作浏览器通过。日志、截图和JUnit默认在work下，不提交用户数据。具体测试总数、通过/失败与原因见TASK4_REPORT。

独立生产措施管理页面仍明确占位；本次不增加认证、生产调度或真实生产库连接。任务5将继续联调、补齐页面、错误修复和运行验收。
