# 任务2：数据接入与模拟场景说明

## Excel导入契约

支持xlsx，默认选择“测量数据”工作表，否则选择第一张表，也可显式指定表名。首行是表头；表头不能空或重复。上限25MiB、50万有效数据行、100列；解压内容上限200MiB。完全空行跳过，错误行号保留源Excel实际行号。

统一接口 `DataSource.read_measurements(start,end)` 使用带时区半开窗口 `[start,end)`，返回 `MeasurementRecord`。`ExcelDataSource`负责映射与转换，`MockDataSource`提供确定性记录；`DatabaseDataSource`仍为注入内存记录的测试桩，不连接外部生产数据库。

### 三步流程

1. `POST /api/v1/excel/preview`，multipart上传 `file`，可选表单 `sheet`。返回任务ID、文件SHA256、工作表/表头、前5行原始预览、建议映射和建议单位；不会创建井或测量记录。
2. `POST /api/v1/excel/jobs/{id}/confirm`，提交显式确认、映射、源单位、时区、演示标记和新建井选项。
3. `GET /api/v1/excel/jobs/{id}`查看统计，`GET /api/v1/excel/jobs/{id}/report`下载全量错误行xlsx。JSON响应只展示前100条错误，下载报告包含全部失败行。

确认请求示例（标准字段→源列名）：

```json
{
  "confirmed": true,
  "mapping": {
    "well_number": "井号",
    "measured_at": "时间",
    "instantaneous_flow_m3_h": "瞬时流量(m³/d)"
  },
  "units": {"instantaneous_flow_m3_h": "m³/d"},
  "timezone": "Asia/Shanghai",
  "is_demo": true,
  "create_missing_wells": false,
  "default_area": "演示导入工区"
}
```

井号和时间必须映射，并至少选择一个动态参数。同一个源列不能映射到两个标准字段。重复语义别名（例如同表同时出现“井号”“井名”）不擅自选择，清空该建议让用户确认。

自动识别“井号/井名/气井编号”“时间/采样时间/采集时间/生产时间”等中文别名与标准英文字段；支持括号单位和常见单位后缀。未知列忽略，不以猜测替代确认。

### 时间、空值及数值

推荐 `2026-10-01T08:00:00+08:00`。Excel原生日期或无时区日期字符串按用户确认的时区解释，再转UTC。拒绝无效时间、now/today等相对时间，以及无法明确解释的夏令时边界，避免重复导入生成不同时间。

部分参数为空时保存NULL和 `缺失:字段名` 质量标记；井号/时间为空或全部参数为空则整行失败。数值字符串可转换；公式、布尔值、NaN、Infinity等拒绝。有限负值保留并标注待核实，温度可为负。这些仅为接入校验，不是生产异常分析。

### 单位

| 参数 | 可选源单位 | 标准单位 |
|---|---|---|
| 油压、套压、回压 | MPa、kPa、Pa、bar | MPa |
| 瞬时流量 | m³/h、m³/d、万m³/d、万m³/h | m³/h |
| 累计流量 | m³、万m³ | m³ |
| 温度 | ℃、K | ℃ |
| 产液量（暂定） | m³/d、m³/h | m³/d |

“万方/天”可识别为“万m³/d”。这里只做量纲换算，不执行标况体积换算或表压/绝压换算；来源口径须保持一致。累计量发生复位也保留原值，交由任务3识别，不在导入阶段擅自修正。

### 关联、幂等与事务

按井号查找稳定Well UUID，修改井号不会改历史UUID。未知井号默认逐行失败；显式允许创建时才按指定工区建井。

数据库以 `(well_id, measured_at)` 唯一约束最终去重，使用PostgreSQL `ON CONFLICT DO NOTHING` 后核对数值。相同键且七参数数值一致视为重复；不同数值报告冲突，保留数据库已有数据。文件内部同键先保留第一条有效记录，后续同值计重复、异值计失败。

同一导入任务由行锁防止并发重复确认，已处理任务再次确认返回原报告；重新上传同文件产生新的审计任务，但不新增重复测量。新井也通过井号唯一键处理并发。一个确认请求内，成功记录、统计和报告一并提交；可恢复的行错误部分成功，数据库/文件级错误整体回滚。当前是同步导入，没有后台队列；大文件需要等待。

上传原文件保存到运行机器的 `work/imports/{任务UUID}.xlsx`，路径不采用用户提供文件名。确认前校验文件哈希，报告文本不会执行用户输入的Excel公式。没有向GitHub上传用户导入的文件；仓库内的xlsx均由固定种子生成。

当前Excel只导入测量表，不自动解释措施、配置等其他工作表。完整Mock批次通过生成接口或生成脚本 `--load` 将井、配置、工具、措施、操作、测量统一入库，避免默默丢失关联信息。

## 模拟数据

默认1000井、14天、逐小时采样，起始2026-10-01 UTC，固定种子20261021，生成器版本mock-v1。数据缺失场景每口故意缺少6个采样点，因此总量是 **335538**，并非1000×336。

“可信正常”在这里仅是已知模拟场景的测试预期，不是本阶段实际分析结果。例如计划停井只有结合计划及可信数据才能在任务3筛除。算法不得读取场景名或预期标签来作判断。

流量与共同低频扰动共同驱动背压、温度；油压含简化流动阻力项，套压关联油压。积液场景另加压差扩大、产液变化；冻堵场景叠加低温和压力关联；累计量使用逐小时梯形积分后添加指定复位或冻结。所有关系只是演示设计，不是井筒物理仿真或现场阈值。

每井提供有效配置、工具；泡排与排采事件带有效区间，周期井有每天开/关井计划。部分稳定演示井配置注醇或其他排采方式，并记录已结束的注醇/机械排液事件，补充生产方式覆盖。默认共1000条配置、1000条工具、206条措施和2310条操作事件。

逐井预期清单包含井号、场景、状态、标签和场景起点，随manifest与xlsx“场景预期”工作表导出；UUID稳定，固定随机流按井独立，xlsx元数据和压缩条目时间也固定。

`POST /api/v1/demo/generate` 必须提交 `confirmed:true`；默认1000井，可配置13至1000井、4至31天。它使用专用事务锁，并记录生成签名；重复生成同配置返回already_loaded，不重复写入。相同种子、天数和起始时间下，支持旧版600井向1000井扩容，只追加新井及其配置、工具、措施和曲线。通过来源签名、稳定UUID、逐井采样数量及时间范围核验旧批次，保留原记录。其他生成配置、人工井号冲突或不完整历史数据会拒绝整个批次，不覆盖、不自动清库。

## 验证和边界

标准回归覆盖全部13场景、固定种子与xlsx可重复、参数相关性、累计积分、事件时刻关联、空值/错误时间/公式、单位转换、映射确认、冲突保护、重复导入及报告。前端组件测试验证确认操作和切换文件行为。

任务2不创建AnalysisRun、WellAnomaly或WellStatusSnapshot，不给出积液/冻堵诊断，不声称正常井已经被分析引擎筛除。真实库接入依然是测试桩。完整规则执行及原任务书中的异常筛查验收在任务3实现。

## 扩容到1000井

网页及生成脚本默认1000井、14天，共335538条测量。旧600井批次升级只新增400井、134214条测量；返回的added_wells和added_measurements供界面显示本次增量。重复点击新增0。已有三行导入样例使用独立井号，数据库总井数可能因此超过1000，属于正常现象。

Excel行上限从25万提高为50万，完整默认文件约23MiB，在25MiB文件和200MiB解压上限内。更大时间范围或更多井的文件仍须按限制拆分。历史600井验收报告保留，现行结果见SCALE_1000_REPORT.md。
